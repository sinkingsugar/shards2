## 2026-10-09-30677d3-claude-e6e0de#F1
- Disposition: fixed
- Change/reason: the amplification was not only the table conversion. With it fixed, four more walks over the shared value remained, each path by path at every read: `Var::type_of` (the argument's type), the compose cache key (`default_hash` hashes the whole `WireDef`, every read's constant included), `Type::admits` (output checks in debug builds; in release, compose-time results and host values at `set_var` and `spawn`), and equality (`reload_preserving` compares old and new definitions, whose constants are separately built copies). The fix applies to all five:
  - `crates/shards-core/src/var.rs`: `into_struct_tables` (and `Table::into_struct`), `type_of` and `PartialEq` for `Var` and `Table` remember the result per storage they meet that is shared elsewhere (`Storage`: the address, plus a struct table's shape; `Arc::strong_count > 1`), so storage held in many places within one value is visited once. Storage held once is reached once, through its one holder, so nothing else is remembered. The map (`Seen`) is created at the first shared node, so a walk over a value that shares nothing allocates nothing and seeds no hasher. Conversion keeps sharing: the converted copies stay one value.
  - `crates/shards-core/src/types.rs`: `Type::admits` the same way, per (type, storage).
  - `crates/shards-core/src/shard.rs`: `Hash` for `ParamValue` hashes at most the first 64 nodes of a value (`Var::hash_prefix`, `Var::HASHED_NODES`), consistent with equality; values differing only past the prefix cost one equality check in the cache's candidate list. `Hash` for `Var` itself is unchanged.
  - Documented in docs/metaprogramming.md §2.5 (Constants) and docs/values-and-types.md (Equality, hashing...).
