## Changes to review

- `crates/shards-core/src/inline.rs`: immutable, compose-selected builtin instructions and one executor shared by both schedulers. Selection uses Rust implementation identity rather than shard names. Covers Const/Get/Set/Ref/Update/Inc, specialized Int/Float/Float4 Add, Take and non-clearing Push.
- `compose.rs`, `shard.rs`, `shards/leaf.rs`, `flow.rs`, `stackless/mod.rs`, `lib.rs` in the same crate: internal optimization hooks, compiled instruction arrays and execution-segment boundaries. Normal node instantiation and cleanup remain in place. Generic host shard activation signatures remain unchanged.
- The accumulator borrows input, immutable constants, frame slots or call-local scratch through raw pointers. Frames are exclusively borrowed and cannot resize; segments contain no arbitrary callbacks or suspension. Writes consume their inputs before replacing storage and reanchor the accumulator. Segment exit clones an owned snapshot before a generic shard, nested flow or suspend boundary.
- Numeric results use `MaybeUninit<Var>` restricted to explicit non-owning numeric variants, avoiding general destructor dispatch. General results use drop-managed scratch. Float4 + Float4 adds f32 lanes directly and emits packed SIMD `addps` on the measured x86-64 release binary. Checked integer overflow and mixed scalar/vector fallback are retained. The Var enum layout itself is unchanged.
- `crates/shards-core/src/shards/data.rs`: shared Take helper and Seq.Make/Table.Make output buffers in instance state. Unshared buffers are reused; saved outputs force new storage. Non-clearing Push gets a builtin path; clearing Push retains its iteration-aware implementation.
- Shared acceptance regressions cover assignment aliases and snapshots across suspension/nested writes. Frontend regressions cover retained constructor outputs. Executor unit tests cover differential owned execution, numeric behavior/overflow, boundary snapshots, Take followed by owner replacement, and self-push.
- `crates/shards-core/examples/bench_depth.rs`: last tested depth reduced from 64 to 32 to fit the current 48-level compose limit. The same adjustment was applied to the isolated baseline benchmark build.

## Measurement evidence and limits

The [report](../../docs/vm-execution-benchmarks.md#builtin-executor-follow-up-2026-10-05)
is the detailed source of results and method; [committed artifacts](../../bench/vm-execution/results/2026-10-05-inline/)
contain samples, calibration, medians, slopes, script hashes, runtime source
hashes, the SIMD excerpt and scheduler reruns. No temporary file from the
implementation session is required to inspect the evidence.

All 25 matched workloads ran at widths 0/8/64/256, with three independent
processes and nine retained samples per engine/cell, CPU 2 on the documented
Linux i9-14900KF machine. Both runtimes used their documented release builds.
All calibration, warmup and measured result/count checks passed. No builds
or other benchmark jobs ran concurrently. The optimized binary was measured
from the working tree based on `98a75c6`; `runtime-source.sha256` identifies
its core sources and the resulting implementation is committed in `7c974be`.

Selected 256-motif stackless / 1.x median time ratios: integer Add 0.63×,
Float Add 0.97×, Float4 Add 1.00×. Both 2.0 schedulers are similar. These
are Add chains, not evidence of parity for every arithmetic operator/shape
or entire applications.

Remaining measured gaps: sequence construction 8.26×, table construction
5.67×, table Take 3.66×, shared-sequence Push 3.45×; independent string
assignment is around 2×. The requested 2× target is not achieved across
all workloads. These are known measured limitations, not newly reviewed
correctness findings. Cached/fixed-field table access, construction ownership
costs and further math specializations remain follow-up work.

Three alternating rounds of instance/depth benchmarks against `98a75c6`
verified work counts. The 10,000-instance workload improved on both backends,
with unchanged instance state/heap for that workload. It does not exercise
constructor buffers. Stackless depth 32 increased about 2.1%; other measured
depths improved. Compiled instruction-array memory and arbitrary application
performance have not been established by these hot-chain measurements.

2. Equivalence to generic shard semantics: mixed numeric types, overflow, Float4 edge values, output-checks, Push clearing, nested control flow and suspension on both schedulers.
