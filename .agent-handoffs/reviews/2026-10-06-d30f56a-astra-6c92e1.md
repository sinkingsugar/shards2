## F1 — P1 Keep Type::admits independent of output-checks

Location: crates/shards-core/src/types.rs:329-340; stackless/runtime.rs:174-181,364-385.

For a fixed expected table and a struct value, admits compares shapes but skips all field types when OUTPUT_CHECKS is false. A fixed {x: Int} therefore admits a struct {x: String} in a normal release build, while the equivalent Map value is rejected. This API is used for real host admission (Mesh::set_var and spawn), not merely optional native-output assertions.

Regression: build a Table::with_shape(Shape::new(["x"]), [Var::string("wrong")]); assert that Type::fixed_table([("x", Type::int())]).admits rejects it in release without output-checks, and that Map and Struct agree. Exercise set_var/spawn too.

Keep full semantic admission unconditional. If a shape-only check is useful, give it a separate API and use it only where field-type validity is independently guaranteed.

## F2 — P1 Failed stateful migration detaches the old tree before cleanup

Location: crates/shards-core/src/stackless/engine.rs:382-399,447-479.

prepare_function_call takes c.children into a local old vector and changes c.function before invoking migrate_component with ?. If building the replacement returns Err, execution exits before the loop cleaning old children. The handles are dropped, but old frames remain in the arena without an owning continuation link. Engine::cleanup traverses from the root through those links, so it cannot logically clean the detached old states. A Maybe catch and repeated replacements can retain unreachable frame trees; eventual arena destruction only drops Rust storage, not shard cleanup.

Regression: run a stateful component with a cleanup-counting resource, accept an Apply reload whose replacement instantiate fails, catch it with Maybe, then retry/cancel. Every successful initialization must get exactly one cleanup and no unreachable arena frames may remain.

Keep old ownership attached until commit, or use guaranteed cleanup/rollback ownership around the migration attempt. Decide whether a failed attempt retries from retained state or explicitly reset state; neither may orphan it.

## F3 — P1 Recursive-group pinning is broken by direct edges within the group

Location: crates/shards-core/src/stackless/engine.rs:362-404, especially Direct selection against ctx.function_body and ctx.table.

Lazy back edges resolve from the parent scope's pinned table, but Direct edges always select against the newest mesh revision and give the child ctx.table(). In mutual recursion A -> B -> A, composing from A creates a direct A -> B edge and a lazy B -> A edge. After a reload, an old recursive chain can enter old A through the pinned lazy edge, then select new B through A's direct edge. A newly entered direct child also receives the latest table, not the group's pinned one. Thus an active recursive group can mix revisions despite the documented contract.

Regression: suspend B in an A/B recursive chain; reload B with a distinguishable result/effect; resume so it calls A and then B again. Every member entry in that original chain must use the old group; an independent new entry should use the new group.

Represent group membership explicitly and use the pinned group registry for every internal edge, not only syntactic back edges. Calls outside the group may retain normal boundary reload behavior.

## F4 — P1 Reload reset admission compares the initial code, not the live component revision

Location: crates/shards-core/src/stackless/runtime.rs:265-290 versus engine.rs:380-390.

validate_reload obtains old from instance.wire.functions, which remains the original compiled wire registry for retained roots. Runtime component selection advances independently through c.function. On subsequent reloads, admission/reset reports therefore compare the candidate to the initial body rather than the component actually holding state.

Concrete regression: under ResetPolicy::Reject, v0 Counter has Keep(n 0); v1 adds Keep(extra 0), an allowed addition. Tick so the component adopts v1. v2 removes extra. Validation compares v0 to v2 and sees no removed slot, while migration compares the actual v1 body to v2 and discards extra. The reset policy is bypassed. The same issue needs tests for components that have not yet adopted the preceding revision and old calls still in flight.

Validate against actual retained/selected component revisions and their pending transitions, not just the root's original dependency registry. Reset reporting should reflect all live source states that may migrate.
