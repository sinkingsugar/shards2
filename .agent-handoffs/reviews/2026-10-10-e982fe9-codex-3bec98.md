## F1 — P2 Compare dependency bytes without lossy UTF-8 conversion
- Location: `crates/shards-lang/src/watch.rs:93-95`.
- Evidence: `binary_edit_is_a_new_revision` loads `@read("data.bin" bytes: true) | ToHex` with file contents `[0xff]`, lets the dependency observation stabilize, then changes the contents to `[0xfe]`. Four subsequent polls (110 ms apart) produce zero reloads; one was expected. Both byte sequences become the same replacement character through `String::from_utf8_lossy`, so `Changes` sees identical observations even though the program's value changed from `ff` to `fe`.
- Impact: `watch` silently keeps stale binary resources loaded by the new `bytes: true` feature. Other invalid UTF-8 edits can collide the same way.
- Suggested direction: keep a structured observation containing exact bytes (and a separate read-error variant), or fingerprint the original bytes with unambiguous boundaries. Do not decode binary dependencies for change detection.

## F2 — P2 Track failed file resolutions so creating a dependency retries loading
- Location: `crates/shards-lang/src/session.rs:371-375` (`Recording::read`), with the dependency loop at `crates/shards-lang/src/watch.rs:89`.
- Evidence: `creating_a_missing_include_retries_the_revision` starts with `@include("lib.shs")` followed by `1`, while `lib.shs` is missing. The initial load is rejected. Creating the missing file, with no main-file edit, yields zero subsequent reloads over four polls; one was expected. `self.inner.read(from, path)?` exits before recording anything, so the watcher never observes that path. The same path handles failed `@read` calls; deleting a previously loaded dependency also drops it from the next attempted load's dependency set.
- Impact: a user cannot recover a watched program by creating/restoring the very file named by its diagnostic; they must edit the main script or force a restart. This breaks dependency-driven recovery.
- Suggested direction: retain attempted resolutions, including missing candidate paths and include search paths, as watch dependencies. The Files/Recording interface may need to expose resolution attempts separately from successful reads.

## F3 — P2 Refresh the observation when loading discovers dependencies
- Location: `crates/shards-lang/src/watch.rs:86-105` and `:113-117`.
- Evidence: `unchanged_dependencies_do_not_reload_twice` uses an existing empty `lib.shs` and main source `@include("lib.shs")` followed by `1 | Log | Math.Divide(0)`. With no edits or forced restart, four normal polls produce two `Reloaded` events and logs `["1", "1"]`, instead of one initial load and one log. The first admitted observation is built while `session.files_read()` is empty. Loading populates that list, but `changes.attempted` still holds the observation without dependencies. The newly appended dependency bytes then appear to be an edit on the next stable sample. `reload_preserving` retries the failed entry, replaying its effects.
- Impact: any newly discovered dependency causes an unnecessary second compilation/reload. A failed entry can repeat I/O or other effects despite no source change, and hosts receive duplicate reload callbacks.
- Suggested direction: reconcile the watcher's accepted observation with the dependency set and contents actually consumed by the load. Preserve detection of real concurrent file changes rather than blindly marking a fresh, unverified read as accepted.
