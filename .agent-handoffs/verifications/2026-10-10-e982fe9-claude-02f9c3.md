## What changed and where to look

Suggested focus, in order of risk. Line numbers are at `e982fe9`.

1. **Hand-written ownership of `Var`'s storage (new unsafe code on the hottest type), `crates/shards-core/src/var.rs`.** Adding `Var::Bytes` pushed the derived drop glue past LLVM's inline threshold and made the VM suite 10 to 88 percent slower, so storage variants (`String`, `Seq`, `Table`, `Bytes`) now hold `ManuallyDrop` payloads and `Var` owns them by hand, as 1.x's `destroyVar`/`destroyVarSlow` (docs/values-and-types.md §2, docs/runtime-performance-overview.md lesson 7). Claims to break:
   - `Drop for Var` (`:48`) releases each storage exactly once through `drop_storage` (`:58`); every other path that ends a value either goes through it or through `drop_value` (`:1315`), never both; `into_seq`/`into_table` (`:189`, `:205`) move the payload out and leave nothing to drop.
   - `clone_value` (`:1333`) is a bitwise `ptr::read` after `retain` (`:555` for `Table`, `Arc::increment_strong_count` for the others): sound only if every storage variant's payload is exactly the `Arc`s counted. `TableRepr::Struct` holds a `Shape` (a `Copy` `u32`) and an `Arc<[Var]>`, `Map` one `Arc<Vec<..>>`. A new field with ownership would break this silently.
   - `drop_value` decrements through `Arc::as_ptr` and `decrement_strong_count`, including the fat pointers (`Arc<str>`, `Arc<[u8]>`, `Arc<[Var]>`), and `Table::release` (`:570`) likewise.
   - `assign` (`:1296`), `release` (`:1352`), `copy` (`:1368`), `assign_copy` (`:1388`): the plain fast paths write or read bits without dropping; check `is_plain` (`:256`) covers exactly the variants without storage, and that no path forgets a non-plain value.
   - `seq_mut` (`:1404`) returns `&mut Vec<Var>` from `Arc::as_ptr` after `Arc::get_mut` succeeded or `unshare_seq` (`:1414`) replaced the `Arc`; the comment claims nothing holds a `Weak` to a sequence. `unshare_seq` copies bitwise, then counts each copied reference before `set_len`, relying on `clone_value` not unwinding (reference-count overflow aborts).
   - Manual `Clone` and `Debug`/`Display` for `Var`.
   Tests: `var::tests::hand_counted_copies_keep_storage_counts` (`:1440`, exact strong counts over every storage kind, both table representations, shared and unique sequences, self-assignment); the inline VM tests. Miri passes on them (below), which shows these tests are clean, not that every path is.
2. **The engine step generic on metering, `crates/shards-core/src/stackless/engine.rs`.** `steps::<METERED, LOCATE>` (`:1326`), `step` (`:1416`), `dispatch` (`:1778`) and `prepare_and_enter` (`:1649`) read the meter only through `let meter = if METERED { ctx.meter } else { None }`; `activate` picks the instantiation from `ctx.meter`. Claim: the runtime instantiation is chosen only when `ctx.meter` is `None`, so dropping the meter there changes nothing, and every metered or located path still charges and records as before (`enter_custom` calls `enter_child::<true>`, which checks at run time). `prepare_and_enter` and `end_invocations` (`:1724`) were moved out of `step` unchanged; check nothing was lost in the move (the `Prepare` failure path unwinds the frame and records the location when `LOCATE`).
3. **`Op::Count`, `crates/shards-core/src/inline.rs`** (`:1012`, `count` at `:642`): one out-of-line call; metered like the `Count` shard (`CountOp::meter`). Selected by type identity in `leaf` like the other builtins.
4. **Compose, `crates/shards-core/src/compose.rs` and `flow.rs`:**
   - A block refuses calls to stateful functions (`stateful-call-in-stateless`, `:1605`), as it refuses `Once`; before, a callee's instance survived between runs of one `Run` and not across two. Is any other way for a block to own persistent state left open?
   - An inlined passthrough `Run` clears its saved input right after restoring it (`:461`, `Op::Clear` moves the value into the accumulator when it reads the slot); the slot stays in `released_slots` for an abnormal exit.
   - `output: None` discards a function's output (`CompiledFlow::discard_output`, `flow.rs:146`: one `ConstDrop(None)` appended, standing for no node; jumps to the end now reach it; origins extended when recorded).
   - `inline_plan` (`:165`) is the inlining decision, now shared with the call-site report; it should be the exact previous condition (the M9 inlining tests pass unchanged). Call sites are recorded only when the mesh asks (`Mesh::record_call_sites`, set by `check`'s analysis) and stored as separate entries in `Occurrences` (`signature.rs`).
5. **Frontend (lower risk), `crates/shards-lang`:** `@include` (each file once per program, by key; depth 64) and `@read` (text or `bytes: true`) through the `Files` trait (`files.rs`: `FsFiles` with `-I`, `MemoryFiles` with normalized paths); multi-file `Source` with per-file lines; the watcher fingerprinting every read file; `Bytes` (type code 51, `Count`, `ToHex`, `BytesToString`, `StringToBytes`). Compose still reads nothing: files are read while loading and recorded (`Program::files`).
6. **Build:** `.cargo/config.toml` aligns non-fallthrough branch targets on aarch64/x86_64 (`-align-all-nofallthru-blocks=4`); `crates/shards-core/build.rs` warns a native release build without it. `scripts/hot-asm.py` skips padding `nop`s and measures the runtime step; CI's new `hot-asm` job fails on any change to `bench/hot-asm/aarch64-apple-darwin.txt`.

Deliberate choices worth challenging: `Set` counts references in place (`assign_copy` inline) while every other copy goes out of line; `seq_mut` allocates twice the length when it unshares; the call-site reason as data; a framed callee still holds its input for the whole call (so the passthrough fix applies to the inlined path only); the alignment flag as a workspace setting rather than a crate-level one.

Open, for the author: tables `rebuild-16` measures about 6 percent slower than M9 in some rounds, within that benchmark's round-to-round spread; the M8 and earlier review follow-ups listed in `docs/current-state.md`.
