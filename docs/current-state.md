Checkpoint: 2026-10-07. Check `git log` and the working tree for later changes. The plan for current work is [golden-path.md](golden-path.md); it overrides older statements elsewhere. Earlier checkpoints, review rounds and the 1.x deviation list are in [history.md](history.md).

## Implemented

- **Core** (`shards-core`): compose once, instantiate many (shared immutable `Compiled`, small per-instance `State`), a content-keyed compose cache with recorded dependencies, frame slots with definite-initialization checks, exactly-once cleanup through shared lifecycle helpers.
- **One scheduler:** `Mesh` runs instances on an iterative, directly resumable engine (`stackless/`: generation-tagged frame arena, central control continuations, iterative initialization and cleanup, a per-mesh call-depth limit). The same engine runs on native, wasm (WASI) and ESP-IDF. The stackful prototype scheduler was deleted after the M4 gate.
- **VM:** compose-selected builtin instructions with a borrowed accumulator; arithmetic near 1.x parity, collections 3 to 4x slower ([runtime overview](runtime-performance-overview.md)).
- **I/O** (`shards-io`): `Http.Get` on a shared Tokio runtime, with cancellation verified.
- **Values and types:** a 32-byte `Var` (f32 `Float2/3/4` behind 16-aligned wrappers), string-keyed sorted tables as struct tables (interned `Shape`, slot-indexed `Take`) or sorted vectors behind the opaque `Table`, fixed/open table types, unions, `Never`, one acceptance rule ([values-and-types.md](values-and-types.md)).
- **Metadata:** every catalog shard has a `ShardDesc`; structured diagnostics with occurrence paths; JSON catalog, describe and search.
- **Frontend** (`shards-lang`, `shards-cli`): hand-written parser with spans and recovery, lowering to wire definitions, `check --json`, `run`, `watch`, state-preserving hot reload ([embedding.md §5](embedding.md#5-warm-sessions-and-hot-reload)).
- **ESP32:** firmware example linked and booted in QEMU for three chips in CI; no physical-board run claimed.

The code accepts the M2 syntax plus M5's `@fn`. `Do` is gone: a named body is a function with its own frame, and `Return` ends the nearest function (or the root iteration).

**Device findings after the day's commits, and their resolution (2026-10-07).** The first firmware run since the M4 gate (`c1ad136`) failed on all three chips: heap exhausted spawning 100 entity instances, and the S3's 128 KiB main stack overflowed composing the 80-deep function chain. Measured natively on the entity workload (`bench_instances 1000`, release, aarch64, back to back): the gate's stackless engine ticks in 95 µs with 1.53 KiB per instance (the gate's example defaults to the deleted stackful scheduler, which measured 104 µs and 1.05 KiB and is not the baseline); after the function commits 465 µs and 1.92 KiB; after M6 as first pushed 133 µs and 2.19 KiB. The reviews' fixes bring it to 102 µs and 1.68 KiB: `Var` back to alignment 16 (a 32-byte value costs the gate's own engine 9 µs and 0.13 KiB on this workload, the plan's accepted price for 1.x's size), a 128-byte frame slot carrying its generation and its flow pointer, stateless call sites keeping their frame trees (leaves that are not stateless are cleaned up at exit and instantiated at entry), the context pointing at the active locals instead of swapping vectors, call preparation as a dispatch request, constant primitive type handles (a call's input check used to intern on every call), a clock-free undelayed `Pause`, `Keep` as a pass-through with the slot initialized at frame creation, and VM instructions for the remaining arithmetic, comparisons and equality. A level of function compose still takes about 6 KiB of native stack (the device keeps `MAX_FLOW_DEPTH` 24; the gate's `Do` path took 3.5 KiB), an open item below.

**VM-level steps (2026-10-07, `51525a6` and `7bac245`).** The reviews' fixes brought the entity workload to parity with the gate; the next commit makes the engine take fewer steps. A stateless, non-recursive call to a straight-line body, a `Repeat` whose body and `until` flow are straight-line, and a `When` or `While` whose predicate and action are straight-line are VM instructions (`VmCall`, `VmRepeat`, `VmBranch`): they run inside the caller's segment, on the kept frame's locals for a call, without an engine step, and a loop checks every site in its body is ready before it starts so a body never runs halfway and then needs the engine (a site is not ready on the first call and after a reload, when the frame path enters it). A call site is prepared and entered in the same step, and a child flow that is leaf code (no shard activation, site, loop, branch or constructor) runs inside the composite's dispatch with its completion dispatched in the same step. Measured with runs interleaved against the baselines (`bench_instances 1000`, release, aarch64): gate 99 µs per tick and 1.66 KiB per instance, e706cfb 101 µs and 1.68 KiB, now 98 µs and 1.68 KiB; `bench_depth --progress` at depth 1/4/16/32: e706cfb 81/81/85/87 ns per instance tick, now 78/81/82/82. Two variants were measured and rejected on the way: evaluating a child flow in the step (its scans and completion round trip cost more than the steps it saved) and inlining the dispatch match into the step (5 percent worse on the entity workload). `7bac245` then inlined the common `Take` reads (the generic runner had grown past the inliner's budget for `take_value`, which the VM suite showed as a 20 to 50 percent slowdown on the take cases). The matched harnesses against 1.x at that commit are in [`bench/runtime-overview/results/2026-10-07-7bac245`](../bench/runtime-overview/results/2026-10-07-7bac245) and [`bench/vm-execution/results/2026-10-07-7bac245`](../bench/vm-execution/results/2026-10-07-7bac245), summarized in [runtime-performance-overview.md](runtime-performance-overview.md#golden-path-refresh-2026-10-07).

**M6 notes.** Alignment 32 was measured against 16 as the plan asked (within 3 percent in time) and kept at first; the review reversed it, because the cost is in size (every frame, instruction and step holding a value grew by a third), so `Var` is 32 bytes aligned to 16 on every target. The VM's `Op` and the engine's `Step`/`Flow` grew to 64 bytes with the 32-byte, 32-aligned value; `Operand` and `Option<Var>` stay 32 through the tag niche. Host-built map tables are not converted to struct tables at the mesh boundary (interning per value would grow the never-freed registry for unbounded key sets); a map value a fixed type admits has exactly its keys, so the slot-indexed read holds for both representations. `TableBuilder` keeps a sorted vector; inserting keys in order appends. Deviation from 1.x: `Float2` components are f32 (1.x used two f64); a vector read back through `Take` is the f32's exact value as a `Float`.

**M5 notes.** A function declared `input: None` ignores its input (so it can start a statement anywhere) and binds `input` to `none`. Mesh bindings inside bodies are resolved against the mesh the body is composed for and recorded as dependencies (the body cache is per mesh), rather than linked as requirement indices at instantiation as §4 sketches; revisit if bodies are ever shared across meshes. Recursion composes against declared signatures (M7); a recursive group's bodies are composed twice (effects fixpoint) and kept out of the cache during the first pass. Under preserving reload, a caller whose own definition did not change keeps its compiled body even when a callee changed, since call sites select callees by name at entry; admission compares inferred effects and mesh access, so an edit that gives a function a new effect or a new mesh access is rejected until the callers are restarted. The entity benchmark's think step is a function now (`bench::functions`), which changes the mixed workload measured in M4; the trampoline gate numbers refer to the `Do` version.

**Stackful deletion (M4, second commit).** Removed: `runtime/` (the coroutine mesh), `shards/stackful.rs`, `corosensei`, both `build.rs` files and `cfg(stackful)`, `--stackful`, the per-scheduler test macros, and the `Backend` trait with its type parameter. What remains is one contract: `Shard` in `shard.rs` (the former stackless one; `Step` is `Flow` plus `Suspend`, `LeafShard` keeps `Flow`), `ShardType::new(desc).implemented_by::<S>()`, non-generic `ComposeCtx<'_>`, `CompiledWire`, `CompiledFlow`, `ComposeCache`; the frontend's `check`, `Program::run` and `Session` take no mesh type, and the `Host`/`SessionHost`/`ReloadHost` traits are gone (`Session::with_mesh` is the host's configuration point). The catalog JSON lost its `backends` field; a described shard without an implementation composes to `not-implemented`. `InstanceMemory` lost `stack_reserved`. The ESP32 acceptance build script no longer expands a macro; it compiles the test files directly.

M2 notes for later milestones:

- Ordinary locals of a *wire* are not yet fresh per root iteration (§3.4); `Keep` is a leaf whose state applies the initial value on first activation. Function invocations get fresh locals (M5); wires still keep theirs across iterations.
- With block scoping, `possibly-uninitialized` is no longer reachable from the shipped shards (every declaration assigns, and nothing declared in a branch escapes); the check stays for host shards that declare without assigning.
- `LeafCtx::iteration` lost its only user (Push's clearing) and is kept for per-iteration locals.

## Open items outside the golden path

- **VM coverage.** A call whose callee suspends, holds a `Keep` or is recursive, a loop or branch with such a body, and a child flow with a constructor still take the frame path; the first call through a VM loop body and the first after a reload take it too (the loop refuses to start unless every site inside is ready). Per 1.x, constructors (`Table.Make`, sequence literals built per iteration), pushes to a shared sequence and a function call per element remain slower (1.1× to 2.5× at width 256, [runtime-performance-overview.md](runtime-performance-overview.md#golden-path-refresh-2026-10-07)).
- **Compose stack per nesting level** is about 6 KiB natively for function bodies (the `Do` path was 3.5 KiB), so ESP-IDF keeps `MAX_FLOW_DEPTH` at 24; the next step is attributing the per-level temporaries (the call-site compose alone is 2.4 KiB) or composing iteratively (golden path §6.3's later item).
- The type registry never frees (shapes included; the soak test records 2 shapes and 2 types per reload that introduces a new record shape); scoped registries are needed for long `watch` sessions.
- The compose cache is unbounded.
- Recursive types, objects, bytes; broader module ports; browser wasm; graphics and physics.
- The external host is porting its shards to 2.0 ([embedding.md](embedding.md)); it must move to the opaque `Table` API (M1) and, with this checkpoint, drop the mesh type parameters from `check`, `run` and `Session`.
